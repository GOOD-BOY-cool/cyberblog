# 写作与部署手册

两个主题：**怎么往里写文章**，**怎么用 GitHub Pages 把它挂到公网**。

---

# 第一部分：写文章

## 1. 一篇新文章的完整流程

### ① 新建文件

放在 `content/` 下，文件名建议 `YYYY-MM-DD-英文短名.md`：

```bash
content/2026-10-20-css-grid-tricks.md
```

文件名只有两个作用：**在编辑器里一眼看出日期和主题**、**没写 `slug` 时用来推断 URL**。真正决定排序的是 front matter 里的 `date`。

### ② 贴 front matter + 正文

```markdown
---
title: CSS Grid 里那个 0 千万别省
slug: css-grid-0fr
date: 2026-10-20
tags: CSS, 布局, 踩坑
summary: minmax(0, 1fr) 里的 0 不是装饰，省掉它，一行长代码就能把整页撑出横向滚动条。
---

`minmax(0, 1fr)` 和 `1fr` 看起来只差一个参数，行为却完全不同……

## 一、问题复现

……
```

### ③ 本地看效果

```bash
npm run dev
```

打开 <http://localhost:4321/>，首页「LATEST_LOGS」里就会出现新文章。改 md 保存 → 浏览器自动整页刷新。

> ⚠️ **新增文件需要重启一次 `npm run dev`**。因为新页面要注册进 Vite 的打包入口表，热更新只处理「已存在的页面」。改已存在的文章不用重启。

### ④ 发布

```bash
git add . && git commit -m "post: css-grid-0fr" && git push
```

GitHub Actions 会自动构建部署，约 1 分钟后线上就能看到。

## 2. front matter 字段

| 字段 | 必填 | 示例 | 作用 |
|---|---|---|---|
| `title` | 是 | `CSS Grid 里的 0 别省` | 页面标题、卡片标题、`<title>`、`og:title` |
| `slug` | 否 | `css-grid-0fr` | 决定 URL `/posts/css-grid-0fr.html`；不写就从文件名去掉日期前缀 |
| `date` | 是 | `2026-10-20` | 排序依据（字符串倒序），也是卡片上显示的时间 |
| `tags` | 否 | `CSS, 布局, 踩坑` | 逗号分隔；**第一个**做卡片右上角角标，全部用于归档页过滤 |
| `summary` | 否 | 一句话 | 卡片摘要 + `<meta description>`，影响 SEO 与分享预览 |

几条硬规则：

- `date` 必须是 `YYYY-MM-DD`，写 `2026/10/20` 或 `10-20` 会导致排序错乱、RSS 时间解析失败。
- `slug` 只用小写字母、数字、连字符。中文能跑但 URL 会被编码成一长串 `%E4%B8%AD`，很难看。
- 冒号后面**必须有一个空格**：`title: 我的文章`，写成 `title:我的文章` 会被 `gray-matter` 解析成 `title` 值为空。
- 标题里出现冒号要加引号：`title: "上线：霓虹边缘 NODE-07"`。

## 3. Markdown 支持范围

本站用 `markdown-it` 渲染，比 GitHub 的 Markdown 略宽松（开了 `html: true`），并做了四处增强：

| 写法 | 效果 | 说明 |
|---|---|---|
| `## 标题` | 带霓虹左边线的 H2 | 自动生成锚点 id；**H2 ≥ 2 个时右侧才出现目录** |
| `### 标题` | H3 | 不进目录 |
| ` ```js ` | 带窗口圆点 + COPY 按钮的代码块 | 构建期语法高亮，语言名写对才有颜色 |
| `| 表 | 表 |` | 表格 | 自动包一层可横向滚动的容器，窄屏不撑破 |
| `- [ ] 待办` | 带勾选框的列表 | `- [x]` 显示为已勾选 |
| `> 引用` | 霓虹左边线的引用块 | 用来做「提示 / 警告」 |
| `**加粗**` `*斜体*` `~~删除~~` | 行内样式 | |
| `[文字](链接)` | 链接 | 站内链接**用相对路径**：`../about.html` |
| `![alt](图片)` | 图片 | 自动加 `loading="lazy"`；但**建议手写 `<img>` 以便指定宽高** |
| 原生 HTML | 直接生效 | `<video>`、`<kbd>`、`<details>` 都能用 |

**不支持**：脚注 `[^1]`、`::: tip` 这类提示块（这是 VitePress 的私有语法）。想做提示框，用引用块代替：

```markdown
> **注意**：`minmax(0, 1fr)` 里的 0 省不得。
```

代码块常用语言名：`js` `ts` `bash` `shell` `html` `css` `json` `yaml` `toml` `nginx` `go` `sql` `python` `diff` `text`（`highlight.js` 支持的语言都能用）。写错语言名不会报错，只是没有颜色。

## 4. 图片与动图

### 放哪、怎么引

图片放 `public/assets/`，构建时原样拷到 `dist/assets/`，引用用**绝对路径**：

```html
<img src="/assets/css-grid-demo.png" alt="栅格被撑破的效果"
     width="1200" height="675" loading="lazy" decoding="async">
```

三个必须：

1. **必须写 `width` / `height`**。不写的话图片加载前高度为 0，页面会跳一下（CLS 变差）。
2. **必须写 `alt`**。它是无障碍的最低要求，也影响 SEO。
3. **站内图片别用外链图床**。图床随时可能防盗链/挂掉，博客是长期资产。

### 动图怎么选

| 需求 | 用什么 | 体积参考 |
|---|---|---|
| 图标、界面示意、数据可视化 | **SVG + SMIL / CSS 动画** | 2~10KB |
| 录屏、操作演示 | **WebM / MP4** | 200KB~2MB |
| 必须用栅格动图 | **动图 WebP / AVIF** | GIF 的 1/5 |
| 实在只能用 GIF | 480px 宽、少帧、`loading="lazy"` | 0.8~2.5MB（尽量别放首屏） |

视频直接写原生标签：

```html
<video src="/assets/demo.webm" width="960" height="540"
       autoplay muted loop playsinline></video>
```

`muted` 和 `playsinline` 缺一不可——否则 iOS 不会自动播放。

## 5. 写作习惯（建议照做）

- **每段 3~6 行**。赛博朋克背景本来就花，长段落会让人读不下去。
- **每节第一句先给结论**，再解释为什么。读者是来扫的，不是来读论文的。
- **代码块前面一句话交代这段代码在干嘛**，别让读者自己去猜。
- **标题只用 H2 / H3**。H1 是文章标题（由 `title` 生成），正文里再写 `# 一级标题` 会破坏层级。
- **`summary` 控制在 40~70 字**，卡片是两行截断，太长会被切掉。

# 第二部分：GitHub Pages 部署

## 0. 前置条件

| 项 | 要求 |
|---|---|
| GitHub 账号 | 有即可 |
| 仓库可见性 | **必须 public**（私有仓库发布 Pages 需要付费计划） |
| 本地 | Node 22+、git 已装 |
| 构建产物 | 不需要提交，CI 会构建 |

## 1. 创建仓库并把代码推上去

先在 GitHub 网页上 **New repository**：仓库名随意（比如 `neon-edge`），**不要**勾选 "Add a README"（勾了会和本地冲突）。

然后在项目目录执行：

```bash
cd cyberblog
git init -b main
git add .
git commit -m "feat: NEON//EDGE 初版"
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

`.gitignore` 已经排除了 `node_modules/`、`dist/` 和根目录那些**生成的** `.html`，所以推上去的只有源码 + 内容，仓库很干净（约 200KB）。

> 如果第一次 push 要求认证：GitHub 早就不用账号密码了，用 **Personal Access Token**（Settings → Developer settings → Tokens）当密码，或者在本机配好 SSH key。

## 2. 打开 Pages

仓库页面 → **Settings** → 左侧 **Pages** → **Build and deployment**：

```
Source:  GitHub Actions      ← 选这个，不要选 "Deploy from a branch"
```

不需要填别的，仓库里已经有 `.github/workflows/deploy.yml`。

## 3. 等第一次构建

点仓库顶部 **Actions** 标签，能看到一个叫 `deploy` 的 workflow 在跑：

```
build  → 配置 Node 22 → npm ci → npm run build → 上传 dist
deploy → 发布到 Pages
```

两个都变绿（约 1 分钟）后，**Settings → Pages 顶部会出现你的网址**：

```
https://<你的用户名>.github.io/<仓库名>/
```

## 4. 之后怎么更新

就一条：

```bash
git add . && git commit -m "post: 新文章标题" && git push
```

push 完自动重建，1 分钟后线上生效。不用管 `dist/`，也不用管 `BASE`——工作流里已经写好了：

```yaml
- run: npm run build
  env:
    BASE: ${{ github.event.repository.name }}
```

## 5. 为什么样式不会丢（`BASE` 机制）

Pages 的项目站点跑在**子路径**下：`https://user.github.io/neon-edge/`。  
如果 `dist/index.html` 里写的是 `/assets/style-xxx.css`，浏览器会去 `https://user.github.io/assets/...` 找，404，页面变白板。

所以构建时必须告诉 Vite「我的站点挂在 `/neon-edge/` 下」，它才会把资源写成 `/neon-edge/assets/style-xxx.css`：

```bash
# 手动构建验证时（只写仓库名，不要带斜杠）
BASE=neon-edge npm run build
```

CI 里由 `github.event.repository.name` 自动填，所以**你什么都不用做**。

> 站内链接（首页→文章、上下篇）用的是相对路径，天然不受子路径影响，这也是本项目坚持「链接相对、资源绝对」的原因。

## 6. 绑自定义域名（可选）

假设你有 `blog.example.com`：

1. **DNS**：加一条 `CNAME` 记录，值指向 `<你的用户名>.github.io`
2. **仓库**：Settings → Pages → **Custom domain** 填 `blog.example.com` → Save → 勾上 **Enforce HTTPS**（证书签发要等几分钟）
3. **站点配置**：把 `scripts/site.config.mjs` 里的 `url` 改成 `https://blog.example.com`（影响 sitemap / RSS / robots）
4. **改 base**：自定义域名是根目录，不再需要子路径前缀。把 `.github/workflows/deploy.yml` 里 `BASE` 那两行删掉（或值留空），重新 push
5. **加 CNAME 文件**（保险）：新建 `public/CNAME`，内容一行 `blog.example.com`，这样换构建方式也不会丢域名配置

## 7. 排查表

| 现象 | 原因 | 修复 |
|---|---|---|
| 打开是 404 | Pages 没启用，或 Source 选成了分支 | Settings → Pages → Source 改成 GitHub Actions |
| 页面白了，控制台 CSS 404 | 构建时没传 `BASE` | 工作流里 `BASE: ${{ github.event.repository.name }}`；手动部署时 `BASE=仓库名 npm run build` |
| Actions 红叉，`npm ci` 失败 | `package-lock.json` 没提交 | `git add package-lock.json` 后重推（本项目已提交） |
| Actions 红了，`Resource not accessible` | workflow 缺 `permissions` | 本项目已声明 `pages: write` / `id-token: write`，检查是否被改 |
| 图片 404、样式全丢 | 用了 `/repo/` 之外的自定义前缀，或把 `dist` 提交后手工改过 | 别手改 `dist`，一律重新构建 |
| 推送了但线上没变 | 构建还没跑完 / 浏览器缓存 | 看 Actions 是否变绿；`Ctrl+F5` 强刷 |
| 只有首页能开，文章 404 | 文章链接带了绝对路径 `/posts/x.html` | 改成相对路径（模板里已用 `root` 变量） |
| 自定义域名打开 404 | base 还是 `/仓库名/` | 删掉工作流里的 `BASE` 那两行 |

## 8. 备选方案：不用 Actions

想手动发也可以（适合不想让仓库带 workflow 的情况）：

```bash
npm run build
npx gh-pages -d dist -b gh-pages     # 需要 npm i -D gh-pages
```

然后 Settings → Pages → Source 选 **Deploy from a branch** → 分支 `gh-pages` / 目录 `/ (root)`。

缺点：每次更新都要本地手动跑一次，且 `BASE` 要自己传。

## 9. 其他托管平台

同一份 `dist/` 也能直接扔到别处，配置只需两行：

| 平台 | Build command | Output | 备注 |
|---|---|---|---|
| Netlify | `npm run build` | `dist` | 仓库已带 `netlify.toml`（含缓存头） |
| Vercel | `npm run build` | `dist` | Framework 选 Other |
| Cloudflare Pages | `npm run build` | `dist` | 国内访问通常比 Vercel 稳 |
| 自己的服务器 | 本地 `npm run build` 后 rsync | — | Nginx 配置见教程第六节 |

**这些平台都部署在域名根目录，不要传 `BASE`。**

# 发布前自检

- [ ] 首页能看到新文章，卡片标题/摘要/日期正确
- [ ] 点进文章，右侧目录有内容，代码块有高亮和 COPY 按钮
- [ ] 归档页标签过滤能筛到新文章
- [ ] 图片有 `width`/`height`、加载后页面不跳动
- [ ] 手机上打开一次，没有横向滚动条
- [ ] Actions 变绿，线上地址能打开
- [ ] 分享链接时 `og:title` / `og:description` 正确
